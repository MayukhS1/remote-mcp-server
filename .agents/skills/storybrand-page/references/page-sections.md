# Page sections, BrandScript feeds, word budgets

Section order is *derived* (StoryBrand five things + SB7 order), not a verbatim 2017-book wireframe. Prefer the site's existing section order when rewriting; use these defaults when drafting cold.

Word budgets are ceilings. Prefer Morse-code bullets over paragraphs. Try cutting half.

## Shared CTA rules

- **Direct CTA:** marry-me ask from BrandScript (Buy / Schedule / Call / Register). Bright, identical, repeated.
- **Transitional CTA:** first-date ask (PDF, trial, webinar, sample). Beside direct; less bright.
- Home / landing: Z pattern (logo top left, direct top right, offer + direct center).

## Home / landing (default wireframe)

| Section | BrandScript feed | Word budget | Notes |
|---|---|---|---|
| Header | Direct CTA label | 2–4 words (button) | Top-right direct CTA |
| Hero | Character desire or offer; Success/Identity subhead | Headline ≤12 words; subhead ≤25; 2 buttons | Offer above the fold; success image note (not the building) |
| Stakes | Failure (~3) | ≤40 words | Salt, not fear dump |
| Value / success | Success bullets | 4–7 bullets, ≤12 words each | Specific destinations |
| Guide | Empathy + Authority | Empathy 1 sentence; ~3 proofs | Light authority |
| Plan | Named process, 3–4 steps | Step title ≤6 words; line ≤15 | Name the plan |
| Explainer | One-liner worked in | ≤60 words | Optional "read more" |
| Lead generator | Transitional CTA | Title + 1 sentence | One magnet per stream |
| Footer / junk drawer | Contact, links | Minimal | No new hero message |

~10 sentences near the fold total across hero + first supporting block.

## Pricing

| Section | Feed | Budget |
|---|---|---|
| Hero | Offer + who it's for (Character) | Headline ≤12; subhead ≤25 |
| Plan clarity | Process plan (how buying works) | 3 steps |
| Tiers | Success outcomes per tier, not feature soup | ≤6 bullets/tier |
| Objection / agreement | Agreement plan fears → promises | ≤5 lines |
| CTA strip | Direct + transitional | Buttons only |
| FAQ (optional) | Internal problem language | Short answers |

One umbrella desire across tiers. Competing hero messages → cut.

## About

| Section | Feed | Budget |
|---|---|---|
| Hero | Customer win / Identity To (not founder bio) | Headline ≤12 |
| Empathy | Guide empathy | 1–2 sentences |
| Authority | ~3 proofs | Short |
| Origin only if it serves the hero | Empathy or philosophical | ≤80 words |
| CTA | Direct + transitional | Required |

Brand-as-hero history walls fail. Founder story only when it proves "we get it" or competence.

## Feature / product

| Section | Feed | Budget |
|---|---|---|
| Hero | External problem solved + desire | Headline ≤12; subhead ≤25 |
| Problem bridge | Villain → internal problem | ≤40 words |
| How it works | Plan steps | 3–4 steps |
| Outcomes | Success bullets | 4–7 bullets |
| Proof | Authority (~3) | Light |
| CTA | Direct + transitional | Repeat once mid-page |

Features are weapons against the villain, not the story. Map each feature line to a problem or success beat.

## Mapping to an existing page

When source HTML/MDX/paste is available:

1. List current headings / blocks in order
2. Assign each a BrandScript module (or `off-script`)
3. Rewrite in place; keep structure unless a block has no story job (then recommend cut or merge)
4. Label output: `## [Existing heading or "Hero"]` then the copy block
